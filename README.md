## Running the prerequisite check

Place the required source files and reference directories beside the main script using the paths listed in `manifest/source_data_manifest.csv`, then run:

```text
Rscript run_analysis.R --check
```

The script resolves inputs relative to its own directory. Keep `run_analysis.R` at the package root and place obtained source files in the relative paths listed in `manifest/source_data_manifest.csv`.

If the package is opened from a temporary unzip directory, the source files will not be found unless they have also been copied there. On the original analysis computer, this v5 package first tries to detect the existing local project-data directory automatically. If that automatic detection fails, point the script to the existing project data directory before sourcing or running it:

```r
Sys.setenv(SARC_IR_DATA_DIR = "C:/Users/taosh/Desktop/list/研究生相关/研究记录★/6. 肌少症多组学/sarcopenia_IR/sarcopenia_IR")
source("C:/path/to/reproducibility_package/run_analysis.R", encoding = "UTF-8")
```

In command-line R, the equivalent is:

```text
set SARC_IR_DATA_DIR=C:\Users\taosh\Desktop\list\研究生相关\研究记录★\6. 肌少症多组学\sarcopenia_IR\sarcopenia_IR
Rscript run_analysis.R --check
```

The missing-file error for `eQTL/Muscle_Skeletal.tsv.gz` means that the GTEx skeletal-muscle eQTL file and its `.tbi` index are not present under the active data directory. These files are large and are listed in the manifest, but are not redistributed inside this package.

## Running the analysis

The current release entrypoint is:

```text
Rscript run_analysis.R
```

The script writes final tables as XLSX and retains analysis-specific intermediate files where required. Runtime can be substantial because the workflow includes large summary-statistic files, MAGMA, LD calculations, colocalization, SuSiE, single-nucleus processing and sQTL analyses.

The MAGMA step writes the resolved P-value inputs under `results_public_release/MAGMA/` and writes the resolver audit and compact QC table under `results_public_release/`. The audit records every duplicate rsID group, the number of matching LD-reference records, the selected source record and any excluded conflict.

After the full analysis has completed, the submission files can also be regenerated without rerunning the computationally intensive upstream modules:

```text
Rscript scripts/04_submission_outputs.R
```

This command reads only the processed-result snapshot frozen inside this package and writes the final files to `submission_outputs/`. When called from `run_analysis.R`, the workflow explicitly passes the current run directory; the script no longer selects inputs according to the shell's working directory.

## Data-access boundary

Large or redistribution-restricted source files are intentionally excluded. Obtain them from the repositories and accessions in the source-data manifest. Permanent source URLs and the terms governing each included processed table should be checked before reuse.

## Interpretation boundary

The 2026-09-16 run regenerated the public-release result tables, manuscript-output files and corrected MAGMA branch in the documented local source-data structure. The 2026-09-17 submission snapshot is the authoritative numerical source for this revision. MAGMA's default SNP-wise mean procedure can invoke stochastic simulation for difficult gene-level integrations; therefore, the package preserves this exact processed snapshot and does not claim bit-for-bit numerical identity for every future full rerun. This does not remove the data-access boundary: large source GWAS, GTEx, GEO and LD-reference files are not redistributed and must be obtained separately.
